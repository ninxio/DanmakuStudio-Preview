# Danmaku Studio 智能批次匹配 V3 开发计划

## 状态

- 立项日期：2026-07-20
- 当前状态：阶段 1–6 已完成
- 产品范围：匹配页中的参考素材、原片素材、音轨选择、批次拓扑推断与候选复核
- 不改变的边界：参考视频只提供时间轴证据；最终产物仍是投影到原片时间轴的弹幕 XML

## 问题定义

真实的 `2 个长参考 × 8 个原片` 批次完整跑完了 16 组粗匹配，但只让 2 个原片进入精匹配。诊断证明主要原因不是素材损坏、目标数量或德语音轨，而是精匹配把“完整一集”错误地限制在 60 分钟以内。与此同时，当前界面把所有组合都当成同等可能，既浪费计算，也把预期无关系的跨组组合显示成“失败”。

V3 要把匹配从“完整笛卡尔积逐组碰运气”升级为可解释的分层系统：

1. 先用文件名、项目分集元数据和顺序推断可能的参考组。
2. 再用低成本音频证据确认拓扑和音轨。
3. 只对可信候选运行完整精匹配。
4. 自动确认只依赖媒体证据；文件名和可选 LLM 永远只是缩小搜索范围的先验。
5. 无关系、需复核和技术失败必须是不同状态。

## 阶段任务

### 阶段 1：解除 60 分钟剧集假设（已完成）

- 把“短媒体完整缓存阈值”和“候选精匹配安全上限”拆开。
- 60 分钟继续作为粗特征缓存是否采用流式模式的阈值，不再决定一集是否可匹配。
- 精匹配窗口按实际资源预算准入，稳定支持至少 90 分钟的单集或电影；更长内容按实际阶段峰值决定是否准入，同时保留 1 GiB 活跃制品上限和 fail-closed 行为。
- 错误文案不再把 60 分钟描述成内容边界。
- 增加 64–74 分钟原片和双长轴候选的 Rust 回归测试。

验收：E01–E08 的时长均可进入精匹配规划；超过资源预算时返回明确的资源限制，而不是“没有 episode-sized 轴”。

### 阶段 2：智能音轨决策（已完成）

- 明确记录语言、默认标记、commentary 标记和内容相似度如何共同决定音轨。
- 已知且冲突的语言降低候选优先级；语言缺失时默认音轨获得轻量先验，但不能压过真实内容证据。
- 当第一、第二音轨证据过近时保留“需选择音轨”状态和候选信息，不静默猜测。
- 批次内复用已确认的同版本音轨偏好。

验收：德语默认轨会优先于英语轨；若参考语言为 `und`，仍通过内容证据选中德语，不因元数据缺失阻断。

### 阶段 3：确定性文件名与分集先验（已完成）

- 新增 React 无关的 `smartBatchPairing` 领域模块。
- 支持 `S03E01`、`S03E01-E04`、`第三季1-4`、`第3季第1-4集`、单集 episodeKey 和 Emby 分集元数据。
- 输出明确的建议组合、置信度、理由和未能解释的素材。
- 默认仅执行高可信建议组合；用户可切换为“分析全部组合”。

验收：示例 2×8 被规划为参考 1→E01–E04、参考 2→E05–E08，共 8 组；3×12 被规划为 12 组，而不是 36 组。

### 阶段 4：大批次分层调度与状态语义（已完成）

- 在界面先展示智能范围摘要和节省的组合数。
- 已由元数据排除的组合显示为“未纳入分析”，不显示为匹配失败。
- 运行状态分为：已找到候选、需要人工复核、没有对应关系、计算环境失败、已取消。
- 保持原生批次的显式 pair 合约和全局非重叠约束。

验收：普通用户能在启动前看懂应用准备分析哪些关系；16 个理论组合不会再生成 16 个“失败”任务。

### 阶段 5：模糊情况与回退（已完成）

- 对已形成音频粗定位候选的关系默认提取视觉证据辅助验证；视觉证据不能绕过音频候选门控单独自动确认。
- 文件名先验与媒体证据冲突时以媒体证据为准，并要求人工复核。
- 对同内容多版本保留显式版本复用选项，不自动扩大一对多权限。
- 缓存键继续绑定媒体身份、音轨和算法版本；重复运行复用粗特征。

验收：配音、无语言标签、超长参考、重复片头和同内容多版本都不会被文件名先验直接自动确认。

### 阶段 6：全量验证、发布与回退点（已完成）

- 运行 Rust、Vitest、Playwright 和 release 验证。
- 用真实 `2×8` 素材按两个智能分组完成受控回归：E01–E04 与 E05–E08 共 8 个正确关系均真实执行，无技术失败，并为每集保留可复核 TimeMap。
- 真实双音轨 E02 在最终排序规则下自动选择默认德语 #1；文件名和音轨元数据只作为受限先验，最终结果仍由内容证据和安全门决定。
- 真实版本差异产生的歧义映射保持 `blocked`，不会因批次执行成功而被自动确认或用于正式导出。
- 更新根目录 `progress.md`。
- 每个阶段创建提交；最终创建 `checkpoint/smart-batch-matching-v3-20260720` 标签。
- 重新生成 release 安装包并记录路径、大小、时间和 SHA-256。

## 完成定义

- 64–74 分钟原片不再被 60 分钟边界误杀。
- 默认双音轨素材可由真实内容证据选择正确轨道。
- `2×8` 和 `3×12` 不再默认运行完整笛卡尔积。
- 文件名/元数据只负责候选路由，不能替代音视频证据或自动确认。
- 用户只在真正存在歧义时做选择。
- 所有变更有测试、进度记录、release 产物和 Git 回退点。
