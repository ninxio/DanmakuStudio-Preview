# Danmaku Studio 易用化重构总方案

状态：实施中；阶段 0–2 已完成，阶段 3 进行中

日期：2026-07-20

阶段代号：Usability V2

概念图：`docs/images/danmaku-studio-usability-concept-v1.png`

> 本方案重构用户如何理解和操作应用，不重写已经可用的对齐、TimeMap、项目序列化和 XML 导出核心。任何精度结论仍以真实媒体验收为准。

## 1. 背景与目标

当前核心流程已经能完成真实任务：导入原片、参考视频与弹幕 XML，建立时间关系，复核映射并导出基本符合原片时间轴的弹幕 XML。现阶段的主要产品问题不是“完全不能工作”，而是用户必须理解太多内部概念，页面密度高、状态语言偏工程化、主次操作不够明确。

易用化重构的目标是：

- 保留所有已经可用的核心功能、数据和非破坏性逻辑。
- 让第一次使用的普通用户按清晰引导完成一次导出。
- 把复杂度留在系统内部，只在需要复核或排错时逐层展开。
- 形成现代、稳定、快速、具备桌面应用质感的 Windows 应用。
- 用智能建议减少机械操作，但不替用户悄悄接受有风险的时间映射。

产品一句话：

> 导入原片和弹幕来源，Danmaku Studio 帮你找出它们的时间关系，检查后导出适配原片的弹幕 XML。

## 2. 不变的产品边界

以下内容在 UI 重构中不可改变：

- 原片是最终观看时间轴；B 站或用户视频只提供弹幕和时间关系证据。
- 应用不剪切、转码或重封装视频。
- 原始 XML 永不直接修改。
- 所有编辑以片段、锚点、偏移、禁用、单条调整和映射规则表达。
- 内部时间统一使用整数毫秒。
- 导出前重新解析并验证 XML。
- 项目文件只保存媒体引用和编辑状态，不嵌入视频。
- 自动结果必须可解释、可撤销、可人工接管。

## 3. 用户与核心场景

### 主要用户

拥有较高质量原片，希望继续使用已有 B 站弹幕或其他 XML 弹幕的普通影音用户。用户知道“哪一个是原片、哪一个是弹幕来源”，但不应被要求理解指纹窗口、置信度阈值、证据包、签名或验收代号。

### 次要用户

需要处理多集合并、删减版、片头片尾差异和局部错位的熟练用户。他们需要精细校准能力，但可以在“高级工具”中主动进入。

### 北极星任务

1. 新建项目。
2. 导入一组原片。
3. 导入一个或多个参考视频及 XML。
4. 让应用自动建议分集和时间关系。
5. 只复核被标记为有疑问的部分。
6. 预览弹幕与原片。
7. 按原片分集导出 XML。

## 4. 体验原则

### 4.1 任务优先

页面标题和按钮描述用户要做的事，例如“添加原片”“开始智能匹配”“检查 1 个问题”“导出 5 集”，不以内部模块名或算法名作为主入口。

### 4.2 渐进披露

默认界面只显示完成当前步骤需要的信息：

- 基础层：结果、风险、下一步。
- 复核层：波形、同步点、片段和版本差异。
- 技术层：算法、诊断、证据和日志。

“高级模式”不是另一套应用，也不复制业务逻辑；它只是把同一状态的更多视图和工具展开。

### 4.3 一个页面，一个主要动作

每一页最多突出一个主按钮。次要操作使用普通按钮或菜单，危险操作必须说明影响。

### 4.4 智能但不神秘

自动匹配应显示易懂结论：

- “匹配良好，可以继续”
- “片头可能多出 36 秒”
- “这一段无法确认，请试听”
- “参考视频可能包含第 3–5 集”

技术置信度只在详情中出现；用户仍能看到系统为何提出建议，以及接受后会改变什么。

### 4.5 稳定和可逆

耗时任务需要进度、取消和恢复；界面不得因后台计算整体冻结或跳动。所有影响映射的操作支持撤销/重做，原始素材始终保持不变。

### 4.6 桌面应用质感

采用克制的 Windows 11 / PowerToys / Codex 风格：清晰层级、稳定布局、紧凑但不拥挤、少量强调色、真实焦点状态。避免炫光、装饰性渐变、巨型卡片和网页营销式界面。

## 5. 新信息架构

顶层继续保留四步主流程，但用结果驱动的名称和状态：

| 步骤 | 用户问题 | 页面主动作 | 完成状态 |
| --- | --- | --- | --- |
| 1 素材 | 我准备好原片和弹幕来源了吗？ | 添加素材 | 素材齐全 |
| 2 智能匹配 | 哪些来源对应哪些原片？ | 开始智能匹配 | 已匹配 / 需复核 |
| 3 校准 | 弹幕在关键位置同步吗？ | 检查问题或预览 | 校准完成 |
| 4 导出 | 输出哪些文件、保存到哪里？ | 导出 XML | 导出完成 |

全局外壳：

- 顶部：项目名称、四步导航、撤销/重做、保存状态。
- 左侧：项目与分集列表，显示最少必要状态。
- 中央：当前任务工作区。
- 右侧：所选对象的上下文面板；没有选择时折叠。
- 底部：后台任务、问题数量和非阻塞通知。
- 设置、帮助、诊断放入应用菜单，不常驻主工具栏。

## 6. 四个页面的重构

### 6.1 素材

默认展示三个清晰的素材区：

1. 原片：最终要一起播放弹幕的视频。
2. 参考视频：弹幕原本对应的视频，可选但自动对齐需要。
3. 弹幕 XML：需要转换的弹幕文件。

优化：

- 支持拖放文件夹和多选。
- 自动识别文件类型、集数与可能配对。
- 导入完成后给出摘要：“5 集原片、1 个合集参考视频、5 个 XML”。
- 缺失内容直接说明下一步，不显示底层扫描和媒体探测字段。
- 重复文件、路径失效、时长异常以可修复问题卡显示。
- 技术媒体信息进入“文件详情”。

### 6.2 智能匹配

这是易用化重构的核心页面，也是第一版概念图的主题。

默认视图：

- 顶部结果摘要：“已找到 5 集，1 项需要复核”。
- 中央按原片排列匹配结果，每行显示参考来源、XML、时间关系和状态。
- 选择一行后显示原片/参考视频双预览与同步波形。
- 只有有疑问的行展开建议和“接受/调整”。
- 一键运行匹配，但不会自动吞掉无法解释的片段。

内部术语翻译：

| 内部概念 | 默认用户语言 |
| --- | --- |
| anchor / fingerprint window | 同步点 |
| confidence score | 匹配良好 / 建议复核 / 无法确认 |
| virtual content segment | 参考视频中的额外内容 |
| verified compatibility | 已检查 |
| manual takeover | 我来手动调整 |
| negative relation | 未找到可靠关系 |
| evidence bundle | 技术详情 |

### 6.3 校准

默认工作区围绕“播放和时间关系”组织：

- 上方是视频预览和当前弹幕覆盖。
- 下方是统一时间尺、双波形和映射片段。
- 列表只突出被系统标记的问题；正常片段可以收起。
- 常用修复以自然语言呈现：“从这里重新同步”“这段没有对应内容”“整体提前/延后”。
- 片段边界、锚点和单条弹幕调整保留在高级工具中。
- 任何调整实时显示影响范围和可撤销提示。

默认不展示 C137、签名、哈希、窗口编号和证据文件位置。

### 6.4 导出

导出页只回答：

- 会导出哪些分集？
- 文件名和目录是什么？
- 哪些项目已检查，哪些由用户接受风险？

主要流程：

1. 显示分集清单和状态。
2. 自动建议 Emby/播放器容易识别的文件名。
3. 对风险项使用普通语言提醒并提供返回复核入口。
4. 导出后显示成功文件、打开文件夹、重新导出。

重新解析验证、媒体身份、签名与完整性检查继续在后台执行；失败时给出用户可行动的原因，并允许展开技术详情。

## 7. 视觉与组件系统

### 视觉基调

- 背景：中性深灰，而非纯黑。
- 层级：依靠明度、间距和细边框，不依赖大阴影。
- 强调色：低饱和青蓝；成功为柔和绿色，需复核为琥珀色，错误为克制红色。
- 圆角：Windows 11 风格的小到中等圆角。
- 字体：系统中文字体；数字与时间码采用等宽数字特性。
- 动效：150–220ms，用于状态过渡、面板展开和任务完成；尊重“减少动态效果”设置。

### 核心组件

- `WorkflowStepper`：四步导航与完成状态。
- `ProjectSummary`：素材、匹配、问题和导出数量。
- `EpisodeList`：虚拟化分集列表。
- `PrimaryTaskCard`：当前唯一主动作。
- `ReviewIssueCard`：问题、原因、影响和操作。
- `MediaPairPreview`：原片/参考视频同步预览。
- `AlignmentTimeline`：波形、映射片段、同步点和差异段。
- `ContextInspector`：按选择显示属性，高级内容默认折叠。
- `BackgroundTaskBar`：进度、取消、恢复和错误。
- `TechnicalDetails`：统一承载诊断信息，避免散落在主界面。

## 8. 智能体验

智能化的第一目标是减少用户判断次数，而不是增加新的 AI 概念：

- 导入时自动归类原片、参考视频和 XML。
- 从文件名、时长和已有关系提出分集配对建议。
- 后台运行已有音频对齐并把结果翻译为少数可行动状态。
- 自动聚合问题，让用户从“检查全部”变成“只检查 1 项”。
- 记住非敏感偏好，例如最近导出目录、布局密度和预览音量。
- 对相似批次复用用户已确认的命名与操作偏好，但必须显示将应用到哪些分集。

第一阶段不引入依赖云端的生成式 AI。核心任务应保持本地可用、可复现，避免媒体上传和额外隐私负担。

## 9. 技术迁移策略

采用渐进式“外壳替换”，避免一次性重写：

### 保留

- 领域模型、TimeMap 与非破坏性编辑语义。
- XML 解析、投影、写出与重新解析验证。
- Rust/Tauri 原生命令和已验证对齐引擎。
- 项目文件兼容性与现有迁移逻辑。
- 已有测试夹具、验收规则和人工接管安全门。

### 新增边界

- 建立面向 UI 的 view model/selectors，把技术状态翻译为用户状态。
- React 组件只消费稳定的展示模型，不重复推导对齐与导出规则。
- 新页面通过现有 store/action 接口调用核心能力。
- 旧页面与新页面在迁移期共享同一数据源，不建立第二套项目格式。
- 技术诊断面板懒加载，避免主流程初次加载大型验收代码。

### 性能重点

- 分集、弹幕和问题列表虚拟化。
- 对大型选择器做可测量的 memoization，避免整页无关重渲染。
- 对齐、波形与媒体探测保持后台任务，所有状态可取消。
- 重型页面和诊断工具按路由拆包。
- 为主交互建立性能预算：输入反馈即时、页面切换稳定、后台任务不阻塞播放。

## 10. 分阶段开发路线

### 阶段 0：冻结基线与行为清单

交付：

- 记录当前可用主流程、项目格式、导出契约和真实样本结果。
- 为素材→匹配→编辑→导出建立稳定的北极星 E2E。
- 建立“必须保留功能”清单和旧 UI 到新 UI 的映射表。
- 记录启动、导入、切页和大列表基线性能。

退出条件：新 UI 可以用自动测试判断是否破坏核心行为。

### 阶段 1：应用外壳与设计系统

交付：

- 新顶栏、四步导航、项目侧栏、上下文面板和后台任务栏。
- 设计 token、常用控件、键盘焦点、空状态、错误与通知。
- 保存布局和非敏感偏好。

退出条件：四页可导航、布局稳定、键盘可达，尚未迁移的旧功能仍能进入。

### 阶段 2：素材页

交付：

- 三类素材的拖放导入。
- 自动归类、批量摘要和可修复问题。
- 文件详情渐进披露。

退出条件：新用户不阅读开发文档即可准备一个有效项目。

### 阶段 3：智能匹配页

交付：

- 一键运行现有匹配能力。
- 分集结果列表、普通语言状态与问题聚合。
- 双预览和同步波形。
- 接受建议、手动调整与撤销。

退出条件：正常批次只需要检查被标记的少数项目；旧匹配功能全部有新入口。

### 阶段 4：校准页

交付：

- 播放、弹幕预览、双波形和映射时间线成为统一工作区。
- 常用自然语言修复动作。
- 高级片段/锚点/单条编辑工具按需展开。

退出条件：高级能力没有丢失，普通用户无需理解内部结构即可解决常见错位。

### 阶段 5：导出与完成体验

交付：

- 分集清单、命名预览、风险说明和导出结果。
- 重新解析验证失败的可行动错误。
- 打开目录、再次导出和返回复核。

退出条件：从空项目到分集 XML 的北极星场景完整通过。

### 阶段 6：收敛与替换旧界面

交付：

- 删除已无入口的旧 UI 组件，不删除仍被核心逻辑依赖的代码。
- 大列表、播放、后台任务和低性能设备专项优化。
- 新 README、用户指南、故障排查和正式截图。
- 可用性走查与真实用户观察。

退出条件：功能对照表无缺项，旧项目可打开，release 安装包和回退点完整。

## 11. 每阶段完成定义

每个阶段至少满足：

- 未改变原始 XML 和项目数据契约，或提供经过测试的向前迁移。
- 对应单元/组件/集成测试通过。
- 北极星 E2E 对该阶段覆盖的流程通过。
- UI 按 `docs/ux-charter.md` 做完整走查。
- 键盘、焦点、空状态、加载、取消和错误状态经过检查。
- release 产物重新打包并可启动验证。
- `progress.md` 更新，创建 Git 提交；里程碑创建 `checkpoint/...` 标签。

## 12. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 易用化时复制核心逻辑 | 用 view model 翻译状态，核心规则仍只有一个来源 |
| “智能”掩盖不确定性 | 风险项必须可见、可解释、可复核 |
| 大爆炸重写导致功能回退 | 按页面渐进迁移，每阶段保留可运行入口 |
| 高级功能被误删 | 先做功能对照表，再移动入口，最后才删除旧组件 |
| 新界面仍然信息过载 | 默认层只显示任务、结果、问题和下一步 |
| 动画与波形拖慢应用 | 性能预算、虚拟化、后台计算、减少动态效果 |
| 视觉更新但流程没有改善 | 以完成北极星任务的操作数、错误率和复核量验收 |

## 13. 可量化目标

在不承诺尚未证明的算法精度前提下，易用化目标为：

- 新用户不阅读工程文档即可完成首个项目。
- 正常五集任务的默认界面不出现内部验收代号。
- 自动结果良好时，用户只需处理被标记的问题。
- 四页中每页只有一个视觉上明确的主要动作。
- 所有耗时操作都有进度、取消和结果。
- 旧项目、旧导出安全门和人工接管能力保持兼容。
- 关键工作流支持键盘操作和清晰焦点样式。

## 14. 案例借鉴

只借鉴任务组织和交互原则，不复制视觉或产品边界：

- [OpenAI Codex app](https://openai.com/index/introducing-the-codex-app/)：借鉴聚焦任务的工作区、清晰的运行状态、主结果与详细过程分层；不引入与本项目无关的代理/工作树概念。
- [DaVinci Resolve](https://www.blackmagicdesign.com/products/davinciresolve)：借鉴按任务拆分页面、在同一项目中快速切换阶段；不照搬专业剪辑软件的高密度工具栏。
- [LosslessCut](https://github.com/mifi/lossless-cut)：借鉴媒体任务直接、时间线明确、撤销和快捷键自然可见；不引入视频剪切语义。
- [Subtitle Edit](https://subtitleedit.github.io/subtitleedit/overview.html)：借鉴视频、波形、时间与字幕对象的同步工作区，以及面向新手的短步骤；不照搬复杂菜单和多窗口布局。

第一张概念图聚焦“智能匹配”页面，表达整体方向而非像素级最终设计：

- 克制的深色 Windows 桌面外壳。
- 四步导航与当前项目状态。
- 左侧分集列表，中央匹配结果与原片/参考视频预览。
- 下方双波形和时间关系。
- 右侧只显示当前选择的复核信息。
- 默认语言是“已匹配、需要复核、额外内容”，技术诊断藏在“技术详情”。

正式实现前需要基于实际组件尺寸制作可交互原型，并分别验证 1280×720、1920×1080 和高 DPI。

## 16. 第一批可执行任务

建议下一次编码从阶段 0 开始，严格限制范围：

1. 建立旧 UI → 新四页/组件/动作的功能对照表。
2. 为当前北极星流程补一个“现有能力不可丢失”的 E2E 基线。
