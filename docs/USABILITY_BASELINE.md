# Danmaku Studio 易用化重构基线

状态：阶段 0 已完成

日期：2026-07-20

上位方案：`docs/plans/2026-07-20-danmaku-studio-usability-refactor.md`

## 目的

本文件定义易用化重构期间不可丢失的行为。它不是 UI 设计稿，也不要求新界面保留旧组件结构；只要用户仍能用更清晰的入口完成同一任务，并且底层数据和安全契约不变，就可以替换旧界面。

## 当前基线

- 项目已经具备素材、匹配、编辑、导出四页。
- 浏览器流程能够完成 XML 导入、时间轴编辑、撤销/重做、单文件导出和重新导入。
- Tauri 流程能够导入带原生内容收据的 XML、批量匹配一对多媒体、逐段复核 TimeMap、人工接管并进入分集导出安全门。
- 分集导出继续要求已配置桌面导出目录、媒体身份复核、可信时间图、项目快照一致和生成 XML 重新解析。
- 当前 E2E 的多媒体北极星场景有意在“未设置桌面导出目录”处失败关闭；原生文件写入和验证由基础设施/Rust 测试覆盖。

## 必须保留的用户能力

### 全局外壳

| 当前能力 | 新外壳归属 | 保留契约 |
| --- | --- | --- |
| 新建、打开、保存项目 | 顶栏/项目菜单 | 旧项目可打开；项目只保存引用和编辑状态 |
| 撤销、重做 | 顶栏与快捷键 | 所有映射和编辑操作继续进入同一历史 |
| 设置中心 | 应用菜单 | 非敏感偏好可保存；密码和 token 不进入明文设置 |
| 新手引导/工作流总览 | 状态驱动四步外壳 | 必须读取实时项目状态，不能退化成静态帮助文字 |
| 全局拖放 | 素材页快捷入口 | 视频必须确认“原片/参考视频”角色 |
| 后台状态与打开目录 | 底部任务栏 | 耗时任务显示进度、取消、失败和完成结果 |
| 可调面板与键盘操作 | 校准工作区 | 关键操作键盘可达并具有清晰焦点 |

### 1. 素材

| 当前能力 | 新入口 | 保留契约 |
| --- | --- | --- |
| 批量导入原片 | 添加素材 → 原片 | 原片始终代表最终观看时间轴 |
| 批量导入 B 站参考视频 | 添加素材 → 参考视频 | 参考视频只提供弹幕来源和时间关系 |
| 导入一个或多个 XML | 添加素材 → 弹幕 XML | 桌面正式导入生成原生内容收据 |
| XML 绑定参考视频 | 素材关系确认 | 每个 XML 的来源明确且可修改 |
| 媒体重连和身份更新 | 文件问题卡/文件详情 | 路径变化不能静默替换媒体身份 |
| 多季/分集和 Emby 时长 | 高级素材工具 | 不得成为首次导入的必填步骤 |

### 2. 智能匹配

| 当前能力 | 新入口 | 保留契约 |
| --- | --- | --- |
| 一对一、一对多和批量自动匹配 | 开始智能匹配 | 同一批次统一启动、显示进度并可取消 |
| 匹配候选列表 | 分集结果列表 | 候选与已确认状态严格区分 |
| 四类时间段判定 | 复核建议 | 共同内容、参考独有、原片独有、无法判断不丢失 |
| 边界、时间图和候选结构调整 | 手动调整 | 继续使用非破坏性 TimeMap |
| A/B 播放复核 | 试听确认 | 播放失败时不能伪造已复核证据 |
| 人工接管 | 接受风险并手动调整 | 必须明确风险和影响范围，不能绕过导出完整性检查 |
| 来源内容段与目标原片关系 | 匹配结果详情 | 多集合并和忽略范围仍能表达 |
| C137 benchmark、证据和算法参数 | 技术详情/开发工具 | 从普通用户主流程移除，但工程能力继续保留 |

### 3. 校准

| 当前能力 | 新入口 | 保留契约 |
| --- | --- | --- |
| 视频和弹幕预览 | 校准主工作区 | 播放状态与时间线保持同步 |
| 时间轴片段排布、移动和裁切 | 高级时间线工具 | 不直接修改原 XML |
| 同步锚点 | 同步点 | 内部仍使用整数毫秒 |
| 版本差异 | “这段没有对应内容”等自然语言动作 | 差异规则继续参与最终投影 |
| 单条禁用与毫秒微调 | 弹幕详情 | 支持撤销/重做 |
| 波形、播放头、缩放和滚动 | 校准时间线 | 大项目下保持可操作 |

### 4. 导出

| 当前能力 | 新入口 | 保留契约 |
| --- | --- | --- |
| 按原片分集预览 | 导出清单 | 每集显示来源、修正规则和弹幕数量 |
| 项目健康检查 | 导出前检查 | 阻断与提示严格区分 |
| 清理失效编辑引用 | 可修复问题 | 操作进入撤销/重做 |
| 选择默认输出目录 | 保存位置 | 正式分集导出不降级为普通浏览器下载 |
| 媒体身份和可信时间图复核 | 后台安全检查 | 失败关闭，不被易用化文案绕过 |
| XML 重新解析 | 后台安全检查 | 失败时不写出成功结果 |
| 批量写入、自动避让同名文件 | 导出 XML | 结果显示真实目录和文件数 |
| 打开输出目录 | 导出完成页/底部任务栏 | 只在真实写出成功后提供 |
| 单时间轴 XML 与检查报告 | 高级导出 | 在迁移期继续保留 |

## 不允许复制到 UI 层的规则

新 UI 只能消费稳定的展示模型，不得重新实现：

- TimeMap 可信度、签名和人工复核判定。
- 媒体身份、项目快照和导出依赖校验。
- XML 解析、投影、序列化和重新解析验证。
- 来源段覆盖、意外未映射和目标分集分组。
- 项目 schema 迁移和历史记录。

第一版展示边界为 `src/domain/project/usabilityViewModel.ts`。它基于现有 `createWorkspaceProgress` 翻译用户语言，不改变任何领域结论。

## 性能记录方式

`tests/e2e/usability-baseline.spec.ts` 每次运行都会在 Playwright 测试结果中附加
`usability-performance-baseline.json`，记录：

- 页面可交互启动耗时。
- 四页逐页切换耗时。
- 10,000 条合成 XML 的导入耗时。
- 导入后的 DOM 节点数和视口。

这些数据用于比较同一机器、同一构建前后的趋势，不作为跨机器的绝对性能承诺。阶段 1 开始前应在当前开发机保留一次基线摘要。

### 2026-07-20 本机基线

运行方式：Chromium、1280×720、Playwright 串行运行；数据取完整 7 项 E2E 中的基线测试。

| 指标 | 测量值 |
| --- | ---: |
| 页面可交互启动 | 325.0 ms |
| 匹配页切换 | 95.5 ms |
| 编辑页切换 | 112.5 ms |
| 导出页切换 | 76.1 ms |
| 素材页切换 | 54.3 ms |
| 10,000 条 XML 导入 | 126.5 ms |
| 导入后 DOM 节点 | 232 |

同一测试单独运行时测得启动 599.3 ms、导入 137.3 ms，说明冷启动和测试进程状态会影响单次数字。后续以多次同环境运行的趋势为准，不以一次结果设置硬阈值。
