# 阶段 6 可用性走查

日期：2026-07-20

## 已完成走查

使用 1280×720 Chromium 和生产 UI 完成：

- 空项目能看到唯一下一步，不阅读工程文档即可区分原片、参考视频和 XML。
- 三类素材准备完成后，唯一主要动作进入智能匹配。
- 匹配默认层只显示任务、结果、问题和下一步；开发验收工具按需加载。
- 校准页可自动排列、播放检查，并用自然语言完成整体偏移、同步点和版本差异。
- 导出先显示检查，再显示逐集名字和数量；兼容导出默认折叠。
- 成功导出组件测试证明真实路径、打开目录和再次导出动作可用。
- 旧项目打开、单 XML 导出、分集投影安全门和 XML 重新解析均有自动回归。
- 键盘导航、焦点、最小视口、错误和阻断状态均由组件或 E2E 覆盖。

## 旧界面审计

- `ExportDialog` 仍服务单时间轴旧项目，并由 E2E 覆盖；改为只有生成 export draft 后按需加载。
- 传统按文件名分 P 导出仍有测试与旧项目价值；保留但折叠，不作为默认主流程。
- `WorkspaceProgressBanner`、检查器、时间线、设置和新手引导均仍有真实入口。
- 工程 benchmark 面板仍是开发验证入口，已从普通主流程隐藏并单独拆包。
- 没有发现可安全删除且完全无入口、无测试契约的独立旧 UI 组件，因此没有为“删除”指标误删领域依赖。

## 首次外部用户观察脚本

参与者：一位未阅读开发文档、未参与项目开发的 Windows 用户。

只给参与者一组原片、参考视频、XML 和一句目标说明，不解释界面。观察：

1. 是否能正确放入三类素材并绑定 XML。
2. 是否理解“需要复核”而不是把得分当准确率。
3. 是否能找到一处固定偏移和一处版本差异的修复方法。
4. 是否能设置导出目录并确认实际输出路径。
5. 在哪里停顿超过 10 秒、误点、回退或询问。

记录完成时间、误操作、求助次数和参与者原话；不要只问“好不好用”。观察后优先修复造成任务中断的问题，再处理偏好型反馈。

## 尚未宣称

本轮完成了工程人员视角的自动与视觉走查，没有伪造外部参与者结果。首次外部用户观察应在下一轮 Beta 中按上方脚本执行；它不改变本阶段代码、旧项目、release 和回退点的完成状态。
