# C137 当前执行计划与结束指标

## 1. 计划目的

本计划把 `C137-high-precision-time-map.md` 的完整技术规范收敛为当前可执行顺序。唯一优先目标是让用户的真实北极星工作流可用：

> 导入 1 个包含 5 集且存在前后片段、局部删减或版本差异的 B 站长参考视频、5 个原片和对应弹幕 XML；程序正确定位 5 集，生成可复核 TimeMap，用户解决必要歧义后导出 5 个与原片同步的 XML。

当前不能以“任务完成”“GPU 已运行”“测试全绿”“产生总体偏移”或“质量门禁成功阻止错误结果”代替上述结果。

## 2. 当前基线

截至 2026-07-19，真实用户运行已经证明：

- 1 个参考与 5 个原片均成功完成媒体身份、容器时间线、音频 PTS 和声谱地标预处理；
- RTX 4090 的 CUDA/cuFFT 后端真实启用，最近一次 1×5 运行约 161 秒；
- 5 个 pair 中只有 pair 1 和 pair 5 进入 fine，pair 2–4 在项目级 coarse/frontier 阶段后没有执行必要 fine；
- 已进入 fine 的 Dark E01 能得到约 `scale=0.999966`、`offset=+22.689s` 的粗关系，但仍有 7 个 ambiguous spans、58 个不稳定边界和未映射训练锚点；
- 没有 pair 产生可保存、可复核、可导出的 TimeMap，用户最终只看到“未匹配”。

因此当前产品状态是“可诊断的对齐研发工作台”，不是可交付的弹幕修正产品。

## 3. 范围和优先级

### 3.1 C137 必须完成

1. 1×N 中每个目标原片得到公平、可解释的关系搜索和必要 fine 评估。
2. 同源音轨场景生成单调、分段仿射、edit-aware 的完整 TimeMap。
3. matched、source-only、target-only、replacement、ambiguous 均有正确双轴范围。
4. 自动结果不足时，用户可以从粗定位开始人工补全或修改 TimeMap，而不是重新选择路径或编辑 JSON。
5. 人工复核后的 TimeMap 能进入正式分集 XML 投影、重新解析验证和批量写出。
6. CPU/GPU 选择、缓存、取消、日志和失败状态真实可理解。
7. 真实冻结媒体达到本计划的准确率、性能和产品闭环门槛。

### 3.2 不作为 C137 算法完成前置条件

- TPM/AIK、硬件不可迁移密钥或受保护进程；
- 企业级 production authority、组织审批和外部证书治理；
- 面向公共发行的商业代码签名证书；
- 与个人桌面弹幕修正无关的匿名化报告发布基础设施。
- 任意 N×M 全局匹配、多对多版本复用和纯视觉回退。

这些可作为后续发布治理工作，不得阻止一个已由真实媒体证明准确、可人工复核且能安全导出的本地产品完成 C137。

## 4. 执行阶段

### 阶段 A：1×5 批次语义修复

任务：

- 复现最近一次 1×5 日志，让 pair 1–5 的 coarse candidate、淘汰原因和 fine 状态逐项可见；
- 修正项目级 Top-K/frontier；每个目标轴至少选择一个最强 coarse 候选作为 mandatory fine seed，禁止一个目标原片因其他目标得分更高而失去自己的必要 fine 评估；
- 对长参考中的互不重叠分集允许同时成立，对真实重叠冲突继续执行全局约束；
- 将任务状态拆成“粗匹配无候选”“等待 fine”“fine 失败”“质量门禁阻断”“匹配成功”，不再统称“完成/未匹配”。

退出条件：

- 用户同一 1×5 素材的 5 个 pair 全部进入必要 fine，或每个未进入 fine 的 pair 都有可复核的“无 coarse 关系”证据；
- 不使用文件名、集号或数组顺序决定正确关系；
- 同一输入重复运行的 pair inventory、排序和淘汰原因完全一致。

### 阶段 B：单 pair 完整 TimeMap

任务：

- 完成 pinned-media 身份守卫，批内只做一次完整内容哈希，同时保留固定句柄和最终对象复核；
- 持久化绑定完整内容身份和工具链的 PTS/探测制品；
- 修复 held-out anchor 参与建图或 fine corridor 的数据泄漏；
- 对无路径区间使用独立局部相关或 mini-DP 恢复，不允许用单个留出点或单个弱锚点填满长区间；
- 保证所有输出 span 连续、单调、双轴守恒，并保留无法判断区间。

退出条件：

- Dark E01 能产生非空候选 TimeMap；
- held-out 数据只用于验收，改变 held-out 坐标不会改变 TimeMap；
- 所有训练锚点要么可投影，要么落在有真实编辑/歧义证据的显式非 matched span；
- 重复运行的对应端点差异不超过 50ms。

### 阶段 C：删减、插入和边界精修

任务：

- 为 source-only、target-only 和 replacement 分别建立真实 Gold；
- 在候选边界两侧执行多分辨率相关与局部重对齐；
- 输出边界点估计、不确定区间、证据来源和失败原因；
- 防止短时 DP 锯齿被误报为大量删减。

退出条件：

- ≥1 秒真实编辑事件达到第 7 节准确率门槛；
- 无证据边界保持 ambiguous/review，不产生伪精确毫秒值；
- 单个真实编辑不会碎裂成多个交替 source-only/target-only 事件。

### 阶段 D：人工兜底与可复核产品闭环

任务：

- 用户可以在双时间轴上新增、拆分、合并和重新分类 span；
- 可直接设置两侧锚点或边界，并由系统重算相邻 matched 仿射段；
- A/B 试听支持循环边界前、边界后和段内检查；
- 人工完成所有必需复核后生成本机可信验证记录；
- 移除“手工来源段存在但没有办法建立可验证 TimeMap”的断路。

退出条件：

- 自动算法故意留下 ambiguous 时，用户无需 JSON、外部脚本或重新导入即可解决；
- 修改任一 span 后旧验证立即失效；
- 人工确认不能掩盖媒体身份变化、结构不连续或未解决歧义。

### 阶段 E：投影和导出闭环

任务：

- 确认候选、来源段、TimeMap revision、XML 内容收据和媒体身份全链唯一绑定；
- 每条弹幕只通过确认 TimeMap 投影到目标轴；
- source-only 弹幕明确计入未映射，target-only 只推动后续映射；
- 导出后重新解析 XML，校验条数、时间范围、排序和目标文件归属。

退出条件：

- 用户北极星项目一次导出 5 个 XML；
- 每个文件对应唯一原片，跨集弹幕为 0；
- 导出文件可重新导入且没有结构错误；
- 任一媒体被替换、TimeMap 被修改或 XML 收据失效时，导出可靠阻断。

### 阶段 F：性能与运行可靠性

任务：

- 去除批内重复全文件哈希；
- PTS、timeline 和 coarse 制品按完整内容身份安全复用；
- 保持单批 native 并发 1，CPU/GPU 内存和进程树有界；
- 日志记录每个素材和 pair 的真实阶段时间；
- 取消时清理 FFmpeg/FFprobe 子进程和 GPU 工作。

退出条件：

- 达到第 7 节性能门槛；
- 冷/热缓存输出 TimeMap digest 一致；
- 连续运行、取消和重启不会出现永久“排队”、残留子进程或缓存污染。

### 阶段 G：真实 Beta 验收与发布

任务：

- 建立 development 和 holdout 两个不可混用的数据分区；
- 保留每个真实样本的媒体身份、人工检查点和修改记录；
- 运行准确率、1×5 北极星、性能、取消、UI 和导出验收；
- 全量测试、更新 `progress.md`、release 打包、Git 提交和 checkpoint。

退出条件：

- 第 7 节所有硬指标均有原始证据且通过；
- holdout 失败必须记录失败类型，不能删除样本或静默放宽阈值；
- 安装包从空项目完成真实北极星走查。

## 5. 每个阶段的交付格式

每个阶段必须交付：

1. 一个可说明用户结果变化的代码切片；
2. 定向测试与至少一个失败回归；
3. 能运行真实媒体时提供脱敏回执；尚无新增真实样本时明确记录合成测试边界；
4. 涉及运行链路时记录阶段耗时和终态；
5. 在可验收里程碑更新 `progress.md`；
6. 在 M2、M3 和最终完成时打包 release，不再为每个内部小切片重复打包；
7. 在可验收里程碑创建 Git 提交；仅 M2、M3 和最终完成创建 `checkpoint/...` 标签。

仅有文档、合成测试或 UI mock 不算阶段完成。

## 6. 真实验收数据最低规模

### 6.1 C137 完成集

- 用户当前《暗黑》第一季 1×5 是强制北极星，必须完成 5/5 候选、人工复核和 XML 导出；
- 再增加至少 4 套真实 1×5 项目，总计 5 套、25 个正确关系；
- 至少 10 个真实负关系，用于证明不会把不相关视频强行标记为高置信匹配；
- 至少 30 个 ≥1 秒真实编辑事件，覆盖 source-only、target-only 和 replacement；不足以稳定计算分类 F1 时，只报告边界误差、区间 IoU 和失败类型；
- 至少覆盖普通重编码、多音轨、前后无意义片段、局部删减、轻微速度漂移和重复 OP/ED；
- 至少 20% 的关系和编辑检查点属于从未参与阈值选择的 holdout。

10 套/50 集属于 C137 完成后的扩大验证，不再作为结束 C137 的前置条件。

### 6.2 数据纪律

- development 可反复调试；
- holdout 只用于里程碑验收；
- holdout 失败时必须修算法、转为显式人工复核或记录产品边界，不能移动样本或改标注；
- 所有真实数据保留内容身份、流身份、Gold revision 和复核来源。

## 7. C137 硬结束指标

以下指标必须同时满足；任何一项失败，C137 保持进行中。

### 7.1 关系和北极星

- 《暗黑》1×5 全部产生可复核候选并完成 5 个 XML 导出；
- 5 套/25 集真实 Beta 中，高置信跨集错配为 0；
- 10 个真实负关系的高置信误匹配为 0；
- 报告自动确认率、人工恢复率和每集人工修正时间，不用小样本宣称 99% 或 99.5%；
- 每个目标原片都得到独立状态，不允许被另一个目标的全局 Top-K 静默裁掉。

### 7.2 matched 时间映射

- holdout matched 检查点投影误差：
  - p50 ≤150ms；
  - p95 ≤250ms；
  - p99 ≤500ms；
  - 单点最大误差 ≤1000ms；
- 自动结果不足时必须形成可编辑候选或显式“无关系”结果，不得只显示笼统未匹配；
- 自动可导出的 TimeMap 不得含未解决 ambiguous；人工确认后的 ambiguous 必须转为明确 span 或保持不可导出。

### 7.3 编辑和边界

- ≥1 秒真实编辑事件报告区间 IoU、漏检、误检和类型分布；
- 起止边界绝对误差 p95 ≤500ms；
- 编辑持续时长误差 p95 ≤500ms；
- 无法达到以上证据的事件必须进入人工复核，不得自动伪装为精确结果。

### 7.4 最终弹幕结果

- holdout 检查点处弹幕最终时间误差 p95 ≤250ms、p99 ≤500ms；
- 5 套真实 1×5 均成功导出 5 个可重新解析 XML；
- 跨集弹幕为 0；
- 未映射弹幕、超出原片范围弹幕和被忽略弹幕都有准确计数；
- 导出前后弹幕文本、样式和原始顺序信息不丢失。

### 7.5 性能

在用户当前 RTX 4090 机器、固定 FFmpeg/FFprobe 和 release 构建上：

- 单个长参考 × 单集原片：
  - 冷缓存 p95 ≤10 分钟；
  - 热缓存 p95 ≤5 分钟；
- 1×5 北极星：
  - 冷缓存 p95 ≤25 分钟；
  - 热缓存 p95 ≤12 分钟；
- 用户点击取消后 2 秒内进入“正在取消”，10 秒内所有子进程结束；
- CPU 模式必须产生与 GPU 等价的 TimeMap，允许更慢，但不能无限排队或改变正确关系。

性能统计至少包含 3 次冷缓存和 3 次热缓存；必须分别报告媒体探测、粗匹配、精匹配和缓存耗时，不能用只执行部分 pair 的运行计入通过。内存和显存记录峰值并检查是否持续增长，但在形成真实基线前不设置拍脑袋的固定 GiB 门槛。

### 7.6 UX 与可靠性

- 首次使用者不依赖外部脚本、JSON 编辑或开发者指导即可完成导入、匹配、复核和导出；
- 不需要在匹配或实验室页面重新选择已导入路径；
- 用户能区分排队、共享预处理、粗匹配、fine、复核、阻断和成功；
- 任何“完成”状态都必须说明是否产生 TimeMap；
- 20 次连续运行（含成功、失败和取消）无崩溃、永久排队或残留媒体子进程；
- 冷缓存、热缓存和 CPU/GPU 的结果语义一致；
- 项目保存、关闭、重开后关系、revision 和导出资格不漂移。

### 7.7 工程发布

- Rustfmt、strict Clippy、Rust 全量测试通过；
- 前端 source audit、ESLint、Vitest、TypeScript/Vite build 通过；
- 四页北极星 E2E 和真实桌面走查通过；
- `progress.md` 记录数据规模、失败分层、准确率、性能和已知限制；
- 最新源码重新打包 release，安装包与便携版均可启动；
- 创建最终提交和 `checkpoint/c137-complete-YYYYMMDD` 标签。

## 8. 阶段性“可用”定义

为了避免等到最终冻结集才第一次让用户使用，设置三个内部里程碑：

1. **M1 可观察**：1×5 每个 pair 都有正确阶段和淘汰原因。
2. **M2 可复核**：用户《暗黑》1×5 至少 5/5 生成候选 TimeMap，并能通过 UI 解决歧义。
3. **M3 可导出**：同一项目导出 5 个经人工复核的 XML，抽样同步误差达到 p95 ≤200ms。
4. **C137 完成**：第 7 节真实 Beta 指标和发布条件通过。

M1–M3 只能描述为阶段可用，不能提前把 C137 标记完成。

## 9. 反停滞规则

- 同一 holdout 失败类型连续两个算法切片没有改善时，必须回到根因和模型选择，不能继续微调同一阈值；
- 禁止为了让当前 Dark E01 通过而加入剧名、文件名、集号、固定时间或特定指纹；
- 禁止降低质量门槛来消除 blocked；
- 性能优化必须证明 TimeMap digest 和准确率不回退；
- 若某项结束指标经真实数据证明不合理，必须保存原测量、说明原因并单独修改本计划，不能在实现代码中静默放宽。
