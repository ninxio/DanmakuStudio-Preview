实现“多视频素材导入与弹幕匹配到原片时间轴”的基础工作流。

## 一、目标

将当前类似“单个参考视频 + 单个目标原片”的媒体导入方式，升级为真正的多视频素材工作流，使用户可以：

1. 在同一个项目中导入多个原片素材；
2. 在同一个项目中导入多个 B 站参考素材；
3. 明确区分两类视频的角色；
4. 将每个弹幕 XML 绑定到一个具体的 B 站参考素材；
5. 在弹幕来源内容段中选择：

   * 具体的 B 站参考素材；
   * 来源开始时间和结束时间；
   * 正片内容或忽略范围；
   * 对应的目标原片；
6. 保存所有新增关系；
7. 正确迁移旧项目中的 `project.media`、`mediaBinding` 和现有来源段数据；
8. 为后续“将弹幕时间投影到原片标准时间轴”准备正确的数据模型。

本任务只完成上述基础工作流，不实现最终的弹幕时间投影算法。

---

## 二、项目核心边界

本项目的核心操作对象和最终输出始终是弹幕 XML。

两类视频的定义如下：

### 原片素材

原片素材是弹幕最终需要匹配到的标准时间轴。

典型来源包括：

* Emby 中的完整版视频；
* 本地完整版视频；
* 对应具体季、集或输出目标的视频；
* 具有标准时长的目标片源。

### B 站参考素材

B 站参考素材是弹幕 XML 原始时间轴的参考证据。

它可能是：

* B 站单集视频；
* 多集合集；
* 长视频；
* 前后包含无意义片段的视频；
* 存在片头、片尾、广告、删减、重复内容的视频。

B 站参考素材不是最终输出目标。

### 明确不做

本任务不得实现或引入：

* 视频剪切；
* 视频分割；
* 视频转码；
* 视频重封装；
* 视频内容导出；
* 视频文件嵌入项目文件；
* 最终弹幕时间投影算法；
* 自动识别删减点；
* 音频、画面或字幕自动匹配；
* 针对特定播放器的输出适配。

最终输出的产品语义应始终是：

> 生成正常、可重新解析的 XML 弹幕文件，并使弹幕时间轴匹配原片标准时间轴。

本阶段尚未实现最终投影与导出时，不得通过 UI 文案或假按钮暗示这些能力已经完成。

## 四、需要实现的功能

### 1. 多视频素材库模型

将项目媒体模型升级为可以保存多个媒体素材。

每条媒体至少需要具有：

* 稳定且唯一的媒体 ID；
* 媒体角色；
* 用户可识别名称；
* 文件名或媒体名称；
* 已知时长；
* 引用类型；
* 当前连接状态；
* 必要的来源摘要；
* 可选的集数或目标标识。

媒体角色至少支持：

* 原片素材；
* B 站参考素材。

不得通过数组索引、文件名、显示名称或当前 UI 顺序建立持久关系。

其他对象必须通过稳定媒体 ID 引用素材。

项目文件不得嵌入：

* 视频二进制内容；
* Base64 视频；
* Emby 密码；
* Emby Token；
* Cookie；
* 其他敏感认证信息。

Emby 相关信息只能保存非敏感摘要。

---

### 2. 旧项目兼容迁移

保留并迁移旧项目中的：

* `project.media`
* `mediaBinding`
* 旧参考视频信息
* 旧目标原片信息
* 现有 `danmakuSourceSegments`
* 可恢复的文件名、时长和媒体摘要

迁移必须满足：

* 旧项目可以成功打开；
* 旧数据不会静默丢失；
* 相同项目重复加载不会不断生成重复素材；
* 保存为新格式后可以再次打开；
* 再次打开不会重复迁移；
* 无法确定媒体角色时，标记为需要确认或显示明确提示；
* 不得仅根据文件名进行不可靠的角色猜测；
* 加载失败时不得覆盖原始旧项目文件。

如项目已有 schema 版本机制，按照现有规则增加版本和迁移。

---

### 3. 多视频导入面板

媒体页必须分为两个清晰区域。

#### 原片素材

文案应明确表达：

> 原片素材是弹幕最终要匹配到的标准时间轴，可以导入一个或多个完整版或目标集视频。

#### B 站参考素材

文案应明确表达：

> B 站参考素材用于理解弹幕 XML 的原始时间轴，可以是单集、合集或存在删减的参考视频，但不是最终输出目标。

两个区域都需要提供真实可用的导入入口。

支持：

* 导入一个或多个原片素材；
* 导入一个或多个 B 站参考素材；
* 多次继续导入而不覆盖已有素材；
* 删除素材；
* 查看素材名称；
* 查看素材角色；
* 查看素材时长；
* 查看素材连接状态；
* 必要时重新连接素材。

不得保留没有实际行为的假按钮。

每条素材至少显示：

* 名称；
* 文件名或媒体名称；
* 角色；
* 时长；
* 状态；
* 来源类型；
* 可选的季、集或输出标识。

未知时长必须显示“时长未知”，不得显示 `0:00`、`null`、`undefined` 或 `NaN`。

---

### 4. 临时浏览器对象 URL

如果浏览器环境中的视频只使用 `blob:` 对象 URL：

* 当前会话中允许使用；
* 项目保存时保存媒体元数据和临时引用状态；
* 重新打开项目后不得将失效对象 URL 标记为可用；
* 必须显示“需要重新连接”；
* 用户重新选择文件后，应更新原有媒体记录；
* 不得因为重新连接而创建重复素材；
* 已有 XML 绑定和来源内容段关系必须保留。

推荐提示：

> 此素材使用的是临时浏览器引用，重新打开项目后需要重新选择原文件。项目中的绑定和时间段信息仍然保留。

---

### 5. XML 与 B 站参考素材绑定

每个已导入的 XML 可以：

* 不绑定参考素材；
* 绑定一个 B 站参考素材；
* 更换绑定；
* 解除绑定。

XML 只能绑定角色为 B 站参考素材的媒体。

不得绑定：

* 原片素材；
* 已删除素材；
* 不存在的媒体 ID；
* 其他 XML。

未绑定时必须显示：

> 该 XML 尚未关联弹幕来源视频，仍可编辑但无法进行可靠的来源段匹配。

绑定关系是项目内部的非破坏性关系。

绑定、更换绑定和解除绑定不得：

* 修改原始 XML；
* 修改 XML 内弹幕时间；
* 删除 XML 记录；
* 自动导出新 XML；
* 覆盖原始文件。

绑定必须保存到项目文件，并在重开项目后恢复。

绑定不得依赖：

* 数组索引；
* 当前 UI 选择；
* 文件名匹配；
* 列表顺序。

---

### 6. 升级 `danmakuSourceSegments`

每个来源内容段必须明确关联：

* 所属 XML；
* 具体 B 站参考素材；
* 来源开始时间；
* 来源结束时间；
* 段类型；
* 对应目标原片；
* 可选的目标集或输出标识；
* 必要的显示名称或备注。

段类型至少包括：

* 正片内容；
* 忽略范围。

正片内容表示：

* 该段参与后续时间轴映射；
* 该段应对应一个目标原片。

忽略范围表示：

* 该段不应投影到最终原片时间轴；
* 可以用于广告、片头、合集间隔、黑屏、重复片段或无意义内容；
* 不要求选择目标原片。

来源段必须验证：

* 开始时间存在；
* 结束时间存在；
* 开始时间小于结束时间；
* 时间不是 `NaN`；
* 时间不是无限值；
* 时间不为负数；
* 已知参考素材时长时，范围不能无提示越界。

来源素材选择器只能显示 B 站参考素材。

目标素材选择器只能显示原片素材。

UI 必须让用户直接看懂：

> 哪个 B 站参考视频的哪一段，对应哪个原片。

至少显示：

* B 站参考素材名称；
* 来源开始时间；
* 来源结束时间；
* 段类型；
* 目标原片名称；
* 当前有效性状态。

---

### 7. 删除素材时的引用处理

删除媒体素材前，检查它是否被以下对象引用：

* XML 绑定；
* 来源内容段；
* 目标原片关系；
* 本任务新增的其他关系。

不得静默删除并留下悬空引用。

采用符合现有产品交互的一种明确策略：

* 阻止删除并列出引用；
* 或经确认后解除关系；
* 或经确认后级联删除相关来源段。

无论采用哪种方式，都必须保证：

* 不产生悬空引用；
* 不自动绑定其他素材；
* 不因数组重新排序而指向错误素材；
* 保存和重开后项目有效；
* 原始 XML 不被修改。

### 8. 保存与重新打开

项目文件必须保存：

* 多媒体素材列表；
* 媒体角色；
* 媒体摘要；
* 媒体连接状态；
* XML 与参考素材的绑定；
* 来源段与参考素材的关系；
* 来源段与目标原片的关系；
* 临时对象 URL 的失效或待重连状态；
* schema 版本或等价迁移标识。

验证完整流程：

1. 新建项目；
2. 导入多个原片素材；
3. 导入多个 B 站参考素材；
4. 导入多个 XML；
5. 给不同 XML 绑定不同参考素材；
6. 创建正片来源段；
7. 创建忽略范围；
8. 给不同来源段选择不同目标原片；
9. 保存项目；
10. 关闭项目；
11. 重新打开项目。

重开后必须恢复：

* 素材数量；
* 素材角色；
* 素材名称；
* 时长；
* 状态；
* XML 绑定；
* 来源段时间；
* 来源段类型；
* 来源参考素材；
* 目标原片；
* 临时素材待重连状态。

## 六、非破坏性要求

本任务的任何操作都不得直接修改原始 XML。

以下操作不得改变 XML 内弹幕时间：

* 导入媒体；
* 绑定参考素材；
* 更换绑定；
* 解除绑定；
* 创建来源段；
* 修改来源段；
* 选择目标原片；
* 保存项目；
* 迁移旧项目。

项目保存不得隐式执行弹幕时间投影。

原始视频不得被修改。

## 七、必须验证的场景

至少验证以下场景：

1. 一个参考视频对应一个原片；
2. 多个 B 站参考视频和多个原片同时存在；
3. 一个 B 站长视频的多个来源段分别对应多个原片；
4. 多个参考视频中的来源段对应同一个原片；
5. XML 未绑定参考素材；
6. XML 尝试绑定原片素材时被拒绝；
7. 来源段尝试使用原片作为来源时被拒绝；
8. 来源段尝试使用参考素材作为目标时被拒绝；
9. 创建忽略范围且不选择目标原片；

11. 开始时间大于或等于结束时间时被拒绝；
12. 删除未被引用素材；
13. 删除被 XML 和来源段引用的参考素材；
14. 删除被来源段引用的目标原片；
15. 临时对象 URL 重开后显示需要重新连接；
16. 重新连接素材后绑定关系不丢失且不重复创建素材；
17. 旧 `project.media` 项目迁移；
18. 旧 `mediaBinding` 项目迁移；
19. 无效媒体 ID 不导致整个项目崩溃；

* 最终 diff 不包含无关重构、调试代码、临时文件或敏感信息。

## 十一、执行方式

先调查现有实现，然后制定最小可行实施计划。

将任务拆分为以下阶段，但在当前 `/goal` 中持续完成全部阶段：

1. 现有模型和迁移逻辑调查；
2. 多媒体领域模型和 schema；
3. 旧项目迁移；
4. XML 与参考素材绑定；
5. `danmakuSourceSegments` 升级；
6. 多视频媒体页 UI；
7. 删除、失效和重新连接处理；
8. 保存与完整往返验证；
9. 自动化测试；
10. `progress.md`、构建、Tauri 和 release 验证。

每个阶段完成后：

* 运行最相关的测试；
* 检查 diff 是否超出范围；
* 修复发现的问题；
* 再进入下一阶段。

不要仅编写计划或文档后停止。

不要因为任务较大而只完成其中一部分。

不要自行扩展到最终时间投影、自动匹配或视频处理功能。
