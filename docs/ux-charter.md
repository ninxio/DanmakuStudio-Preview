# UX 宪法（产品动线与交互铁律）

本文档是所有 UI、交互和功能归置决策的最高依据。任何新功能、重构或文案调整，先对照本文档再动手；与本文档冲突的实现视为缺陷。

## 北极星场景（所有设计决策的唯一裁判）

> 用户导入《暗黑》第一季 5 集原片、1 个五集首尾相连且随机删减的 B 站长视频、对应弹幕 XML。
> 软件自动识别每集在长视频中的位置并吸附，给出删减修正候选；用户复核确认后，
> 分别导出 5 个与原片精准同步的弹幕 XML。全程主要操作 ≤ 10 次。

判断任何设计是否合格的方法：把它放进这个场景走一遍。如果它让场景变长、变难懂、或者用户不知道下一步去哪，它就是错的。

## 产品动线（唯一主线，页面制）

应用顶层只有四个页面，构成单向工作流：

```
[ 素材 ] → [ 匹配 ] → [ 编辑 ] → [ 导出 ]
```

1. **素材页**：集中导入和管理三类素材——原片素材、B 站参考素材、弹幕 XML；完成 XML 与参考素材的绑定。用户离开素材页时应该已经知道"我有什么、它们之间是什么关系"。
2. **匹配页**：产品核心。回答"B 站参考视频的哪一段对应哪个原片"。包含来源内容段编辑、自动匹配（音频对齐）、候选复核。产出是可信的来源段和删减修正规则。
3. **编辑页**：时间轴工作台（预览 + 时间轴 + 检查器）。用于精细人工修正：单条弹幕、片段、版本差异、锚点。
4. **导出页**：按目标原片分组预览导出结果（"第 3 集 ← 长视频 48:12~72:40，应用 2 处删减修正，4231 条弹幕"），健康检查，一键导出全部分集 XML。

任何功能必须归属四页之一；说不清归属的功能不做。

## 交互铁律

1. **一个动作只有一个入口。** 每种素材只在素材页导入；其他位置只能引用已导入素材（下拉选择），绝不再弹文件选择器。全局拖放视为素材页导入的快捷方式，导入后引导用户到素材页确认。
2. **影响范围就地说明。** 任何设置或操作，必须在操作处用一句话说明它影响什么（"此偏移影响当前 XML 的全部弹幕导出时间"），不允许用户猜。
3. **渐进披露。** 默认界面只显示当前步骤需要的操作；诊断信息、算法参数、实验功能一律收进折叠区或"详情"。
4. **状态驱动引导。** 每页顶部有显式完成状态（"5 个原片中 3 个已完成匹配"）；"下一步"在条件不满足时说明缺什么，而不是灰着不解释。
5. **结果语言，不是机制语言。** 主界面文案只说结果："这一段很可能对应第 2 集"、"检测到 3 处删减，共 47 秒"。`sourceAtMs`、指纹窗口、DP 阈值等内部字段只能出现在诊断详情。
6. **候选与已确认严格区分。** 自动算法的一切产出（来源段、删减点、锚点）先以"候选"状态呈现，低置信不自动应用；用户确认后才成为项目状态。
7. **空状态即引导。** 每个列表/面板为空时，必须说明这是什么、为什么需要、下一步怎么做。
8. **无假按钮。** 条件不足时按钮要么隐藏、要么禁用并说明原因；点了没反应的按钮是缺陷。

## 功能归置检查清单（新功能合入前必答）

- 用户在四页动线的哪一步遇到它？
- 用户为什么需要它？不用它会卡在哪？
- 它的入口文案，一个没读过文档的用户能懂吗？
- 它的产出显示在哪里？用户如何确认它生效了？
- 它是否与现有入口重复？若重复，收敛为一个。

## 验收方式

每个涉及 UI 的阶段完成后，必须按北极星场景（或其手动简化版）做完整走查：从空项目开始，到导出分集 XML 结束，逐步截图，确认每一步用户都能看懂"我在哪、我要做什么、下一步去哪"。只有走查通过，阶段才算完成。
